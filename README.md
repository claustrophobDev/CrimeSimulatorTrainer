# CrimeTrainer

Трейнер для **Crime Simulator**. C++/Win32 x64, без внешних зависимостей.
Только офлайн / одиночная игра.

Два бинаря: `CrimeTrainer.exe` (окно) и `CrimeTrainerHook.dll` (то, что живёт
внутри процесса игры). Общаются через общую память.

---

## Функции

| | Что делает |
|---|---|
| Полиция | Гасит вызов копов, подкрепление, спавн машин и дрона |
| Гражданские | Кражи, шум, чужая территория и агрессия больше не замечаются |
| Камеры | Камера выключается штатным `isDisabled`, alarm-RPC заблокированы |
| Датчики и сигнализации | Motion/laser сенсоры, сейфы, кейпады, сигналки машин |
| Бесшумность | Игровой флаг `blockAllNoise` — шума нет вообще |
| Замедление времени | Сутки в 8 раз длиннее, NPC при этом живут обычной жизнью |
| Бесконечная выносливость | Стамина не падает, не включается cooldown |
| Без урона | Накопленный урон откатывается в ноль |
| Остановка времени | Часы стоят. Распорядок дня NPC встаёт вместе с ними, см. ниже |
| Бесконечные патроны | Боезапас докидывается по мере расхода |
| Прочность предметов | Отмычки и инструменты не изнашиваются |

Каждая включается отдельно. Если включены одновременно **полиция** и
**гражданские**, дополнительно глушатся общие реакции NPC (`RPC_AlertToLocation`,
`RPC_PullOutWeapon`, `CheckIllegal`, `TriggerAttack` и т.п.) — но только те, что
реально нашлись в текущей сборке.

Урон и смерть не подавляются никогда. Игнорящего гражданского всё ещё можно
ударить и убить.

### Горячие клавиши

| Клавиша | Что |
|---|---|
| `INS` | Скрыть / показать окно |
| `CTRL+F1` … `CTRL+F11` | Переключить функцию, не сворачивая игру |
| `1`…`9`, `0` | То же, когда окно трейнера в фокусе |
| `↑` `↓` + `Space` | Навигация с клавиатуры |
| `Esc` | Спрятать окно |

## Почему NPC застывают при остановке времени

Если включить **Остановку времени**, NPC перестают менять занятия: кто сидел на
скамейке — будет сидеть, пока не выключишь. Это не баг трейнера, так устроена
сама игра:

```csharp
// NPC.Update()
if (prevHour != WM.enviro.Time.hours && !weaponActive && !checkOut && ...)
{
    SetNewBehaviour();      // внутри: index = prevHour = Time.hours
}
```

Весь распорядок дня выбирается **по номеру текущего часа** и переключается
ровно в момент, когда час меняется. Останавливаем часы — час не меняется —
никто никогда не берёт новое занятие. Внутри текущего занятия NPC продолжает
двигаться (дойти до точки, патрулировать тротуар), но переключиться уже не
может.

Обойти это, оставив часы стоять, нельзя: расписание и есть часы.

Поэтому добавлено **Замедление времени** — оно не трогает `simulate`, а
увеличивает `cycleLengthInMinutes` у Enviro в 8 раз. Часы идут, просто очень
медленно, и распорядок продолжает работать. Если нужно растянуть ночь или
дедлайн заказа — брать надо его, а не остановку.

Обе функции независимы, можно включать что угодно.

## Про баг с застывшими NPC (исправлено)

Главная правка этой версии.

Раньше трейнер глушил `NPC::Sight` и `NPC::Hearing`, подменяя первый байт на
`ret`. Выглядело логично — «методы обнаружения, значит глушим». На деле оба
метода вызываются **каждый кадр из `NPC.Update()`** и они же единственные, кто
сбрасывает `seesPlayer`, `hearsPlayer`, `seePlayerTimer` и `lostPlayerTimer`.

После `ret` эти флаги застывали в том значении, в каком были в момент включения.
NPC, который в тот момент на что-то реагировал, оставался в реакции навсегда:
бросал свою рутину и просто стоял. Отсюда и «все стоят на одном месте».

Теперь вместо патча используются штатные поля самой игры:

```csharp
// NPC.Sight()
if (playerInFOV && ... && !isBlind)  { /* проверка зрения */ }
else                                 { seesPlayer = false; }

// NPC.Hearing()
if (distanceToPlayer <= ... && !isDeaf) { /* проверка слуха */ }
else                                    { hearsPlayer = false; }
```

`isBlind` и `isDeaf` стоят ровно в том `if`, который решает, видит и слышит ли
NPC игрока. Метод при этом отрабатывает целиком и сам всё обнуляет. Никакой
заморозки — NPC продолжает ходить по своим делам и просто не замечает игрока.

Заодно вылезло, что `ignoreEverything` работает хуже, чем звучит: в `Hearing()`
он делает ранний выход (нормально), а в `Sight()` только обнуляет `seesPlayer`
и проваливается дальше, где сенсор через 0.25 с ставит флаг обратно. Одного его
не хватает, поэтому он оставлен как дополнительный, а не основной.

Это отдельная история от остановки времени выше: там NPC не переключают
занятия, а тут они застревали в реакции и вообще бросали рутину.

**Правило на будущее:** прежде чем патчить метод, надо посмотреть, не зовут ли
его из `Update()`. Если зовут — почти наверняка он же и чистит своё состояние,
и `ret` его сломает. Как смотреть — в `docs/HOOK_MATRIX.md`.

Той же болезнью болел `MotionSensor::DetectedPlayer(bool)` — это просто сеттер
для `playerInRange`, и заглушка намертво фиксировала датчик в последнем
состоянии. Убран.

## Ещё одно: `[Networked]` свойства

Camera/sensor раньше выключались записью в поле `_isDisabled`. Оказалось, это
пустая операция: `isDisabled` — это Fusion `[Networked]` свойство, оно читает и
пишет сетевой буфер через `ReadWriteUtilsForWeaver`, а поле `_isDisabled`
используется только для начальных значений из инспектора. После `Spawned()`
запись туда не делает ничего.

Теперь такие поля пишутся через настоящий сеттер свойства. Это же касается
`blockAllNoise` у игрока.

## Как оно устроено

Worker-поток DLL **не вызывает Unity API и не трогает Mono-объекты**.

```
CrimeTrainer.exe
      |  общая память
      v
CrimeTrainerHook.dll (worker)
      |  PostMessage
      v
окно Unity / главный поток
      |
      v
GameController
```

DLL сабклассит окно игры и шлёт приватные Win32-сообщения. Весь `GameController`
крутится из `TrainerWndProc`, то есть на потоке окна — там, где Unity разрешает
трогать свои объекты.

Детект глушится **до** реакции AI: вместо бесконечного сброса `seesPlayer`,
anger, chase level и `callingCops` используются штатные флаги NPC и подавление
конкретных event/RPC-точек входа, с проверкой наличия перед каждым патчем.

Обе стороны шлют друг другу heartbeat. Если лаунчер убили через диспетчер задач,
hook замечает это за 4 секунды и выгружается сам, вернув всё как было.

## Диагностика

Рядом с DLL появляется `CrimeTrainerHook.log`:

```
[OK] SecurityCamera::RPC_TriggerAlarm
[OK] PoliceManager::RPC_PoliceCalled
[SKIP] NPC::CheckIllegal not found/supported
[SKIP-PROTECTED] damage/death path left intact: ...
```

В окне трейнера счётчик `HOOKS` показывает, сколько точек входа удалось
разрешить. Если после обновления игры там 0 — сборка поменялась. У каждой
функции есть своё состояние:

- **НЕТ В СБОРКЕ** — ничего подходящего не нашлось;
- **ЖДЁТ МИР** — нужен загруженный мир или игрок;
- обводка на переключателе — включено, но ещё не применилось.

## Выход

Кнопка **«Завершить»** и крестик делают одно и то же:

1. cleanup на главном потоке игры;
2. возврат оригинальных байт всех патчей;
3. возврат сохранённых полей;
4. снятие subclass с окна;
5. и только после возврата из оконной процедуры — `FreeLibraryAndExitThread`.

`Crime Simulator.exe` при этом остаётся запущен.

Если главный поток игры завис и cleanup не подтвердился, DLL **не выгружается
насильно** — иначе остался бы WndProc, указывающий в выгруженную память. В этом
случае в футере появится сообщение, а трейнер останется висеть.

## Сборка

Windows 10/11 x64, Visual Studio 2026 или 2022 с `Desktop development with C++`,
Windows SDK, CMake.

```bat
build.bat
```

На выходе:

```
dist\
  CrimeTrainer.exe
  CrimeTrainerHook.dll
```

Формат общей памяти привязан к `kSharedVersion`. Если в игре сейчас висит DLL от
старой версии — закрыть игру один раз перед первым запуском новой.
